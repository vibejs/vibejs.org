# البدء

تطبيق vibe.js حزمة واحدة من ثلاثة أجزاء: الواجهة، والخادم، والعقود التي تربط بينهما. تنشئه بأمر واحد، وتفحصه كله بأمر واحد.

## المتطلبات {#requirements}

- Node.js `^24.15.0 || >=26`.
- مدير حزم: pnpm أو npm أو yarn أو bun. الأمثلة هنا تستخدم pnpm.

## أنشئ تطبيقًا {#create-an-app}

```sh
pnpm create vibejs my-app
cd my-app
```

إن كنت تستخدم مدير حزم آخر فشغّل `npm create vibejs@latest my-app` أو `yarn create vibejs my-app` أو `bun create vibejs my-app`. أداة الإنشاء تثبّت الاعتماديات بمدير الحزم نفسه الذي شغّلها.

## بنية المشروع {#project-layout}

| المسار       | محتواه                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------- |
| `contracts/` | عقود الـ API: المسارات مع معاملاتها وأجسام طلباتها واستجاباتها وأخطائها. تتشاركها الواجهة والخادم. |
| `server/`    | الخادم: الوحدات، والمتحكمات (controllers) التي تخدم العقود، والخدمات.                             |
| `ui/`        | الواجهة: مكوّنات `.vibe`، والصفحات، والمسارات، وعميل الـ API ذو الأنواع.                            |
| `AGENTS.md`  | القواعد وفهرس الوثائق لوكلاء البرمجة.                                                              |

## شغّله {#run-it}

```sh
pnpm dev
```

يخدم `pnpm dev` الواجهة والـ API على منفذ واحد، والـ API تحت `/api`. افتح العنوان الذي يطبعه، فتعرض الصفحة الرئيسية الحالة التي تجلبها من `/api/health`. حين تعدّل الواجهة تتحدّث في مكانها، وحين تعدّل الخادم يعيد تشغيل نفسه.

## افحصه {#check-it}

```sh
pnpm vibejs check
```

يجري `vibejs check` كل الفحوص دفعة واحدة: يتحقق من الأنواع في TypeScript وفي قوالب `.vibe`، ويشغّل المدقق (linter)، ويفحص التنسيق، ويشغّل الاختبارات مع قياس التغطية. ينتهي بالرمز 0 إذا نجح كل شيء. وإلا يطبع كل مشكلة مع ملفها وسطرها وعمودها، ورابطًا إلى وثائقها.

## إعداد المحرر {#editor-setup}

ثبّت إضافات VS Code الموصى بها، وهي مذكورة في `.vscode/extensions.json` داخل التطبيق:

- **vibe.js** (`vibejs.vibejs`): تلوين الصياغة، والتحقق من الأنواع، والتلميحات عند التمرير، والانتقال إلى التعريف في ملفات `.vibe`.
- **TypeScript 7** (`TypeScriptTeam.native-preview`): خدمة لغة TypeScript، وهي تفحص ملفات `.vibe` عبر `@usevibejs/language-tools` في التطبيق.
- **Oxc** (`oxc.oxc-vscode`): التدقيق والتنسيق عند الحفظ.

التحقق من الأنواع يشغّل كود المشروع، لذا يحتاج إلى مساحة عمل موثوقة. إن لم تكن إضافة TypeScript 7 مثبّتة أو لم تمنح الثقة للمجلد، يعرض المحرر [VIBE6101](https://vibejs.org/v0/errors/VIBE6101) أو [VIBE6102](https://vibejs.org/v0/errors/VIBE6102) ويكتفي بالتلوين.

لإعداد Neovim والمحررات الأخرى، وللقيود المعروفة وحل المشكلات، راجع [إعداد المحرر](https://vibejs.org/v0/guides/editors).

## وكلاء البرمجة {#coding-agents}

في `AGENTS.md` كتلة من قواعد vibe.js موجّهة إلى وكلاء البرمجة. فيها الأوامر بنصّها الدقيق، والقواعد التي يخطئ فيها الوكلاء أكثر من غيرها، وفهرس للوثائق المرفقة بالتطبيق في `node_modules/@usevibejs/cli/dist/docs`. هكذا يقرأ الوكيل وثائق الإصدار المثبّت. يُبقي `vibejs agents sync` و`vibejs dev` هذه الكتلة محدّثة، فاكتب ملاحظاتك خارج علاماتها. راجع [سطر الأوامر ووكلاء الذكاء الاصطناعي](https://vibejs.org/v0/guides/ai-agents).
